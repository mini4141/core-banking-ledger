# Security considerations

What is in the code, and what is deliberately out of scope for a showcase slice.

| Area | Implementation |
|---|---|
| Input validation | Bean Validation on every request body (`@NotBlank`, `@DecimalMin("0.01")`, currency pattern, leg enum). Invalid input returns `400 VALIDATION_FAILED` without echoing the payload. |
| Money handling | `BigDecimal` and `DECIMAL(19,2)` only. Debits cannot take a balance below zero (`422 INSUFFICIENT_FUNDS`). |
| Replay safety | Idempotency key in Redis plus `UNIQUE (transfer_id, leg)` in MySQL. |
| No PII in logs | Logs carry account and transfer IDs (UUIDs), amounts and trace IDs. Customer names are never logged. Error responses use generic messages. |
| Secrets | Database credentials come from a Kubernetes `Secret` (`ledger-db`). On AWS the password is generated by Terraform (`random_password`) and written to the Secret by `scripts/deploy.sh`; nothing secret is in Git, the Helm chart (AWS values), or images. `.env`, Terraform state and kubeconfigs are gitignored. |
| Least-privilege IAM | audit-service has a Pod Identity role limited to `PutItem`, `Query`, `Scan`, `DescribeTable` on the one DynamoDB table. Fluent Bit's role can only call `es:ESHttp*` on the one OpenSearch domain. No static AWS keys in the cluster. |
| Network | Aurora lives in isolated subnets (no route to the internet) and its security group admits only the EKS node security group on 3306. No SSH, no database port open to the internet, no NAT gateway. OpenSearch's access policy admits the Fluent Bit role and the deployer's `/32` only, over HTTPS (TLS 1.2+), encrypted at rest and node-to-node. |
| CI | GitHub Actions builds and tests only; it never holds AWS credentials. Deployment runs from the maintainer's machine. |
| Internal endpoints | `/internal/accounts/...` is reachable only inside the cluster network (ClusterIP service, not exposed by the console proxy). |

Out of scope here and listed as next steps: authentication and authorisation on the public API (OIDC), mTLS between services, a transactional outbox for Kafka publishing, field-level encryption, and audit-log immutability controls.
